# AGENTS.md

Non-obvious facts for automated edits. Architecture and measured costs live in README.md.

## Rules

- Agent operating routine, git workflow, checks and secrets handling: `docs/AGENT-INTERFACE.md`.
- The world runtime is `src/world.rs` (load, spawn, physics, report), `src/spec.rs` (jayzee object spec), `src/tree.rs` (world tree and cells), `src/runtime.rs` (fixed-step systems) and `src/script/` (rquickjs host and prelude).
- `initialized` in the script host is keyed by `(entity, script)`, not by entity: a policy can rewrite `behavior` at runtime and every newly added script must receive `onJayzee`.
- A character body gets `GravityScale(0)`; the walk scripts integrate `ctx.place.gravity` into `velocity` themselves, so Avian must not add the same acceleration.
- `ctx.sleep()` with no seconds parks the entity until input, a property write or a behavior change wakes it; the input loop wakes every behavior entity before dispatching `onInput`.
- UI render scripts export a default function returning an HTML string; the runtime calls it once per change of the player's state and never needs a DOM.
- Scripted primitives get their compound colliders from `collider(ctx)`; a returned `heightfield` row array becomes `Collider::heightfield`.
- `ctx.changed` diffs every object's `state` across one tick; the cursor clears on read.
- `src/features.rs` owns the native local feature state behind script API calls: deterministic rollback physics worlds, voxel parts, FX/vibe/job/trade/DM records, seeded RNG, timing/view constants, and the `feature-report` JSON line. Host verbs in `src/script/mod.rs` return parsed JSON; prelude code must not wrap `__host` results in `__parse`.
- `createWorld` is synchronous-compatible: the prelude returns a native world object with a `then` method so both `createWorld(...)` and `await createWorld(...)` work without rquickjs async job execution.
- `builtin_exports` must list every name a world script can import from `builtin/<module>`; duplicate names throw at QuickJS module declaration because the generated body declares one `export const` per listed name. The generated module body reads `globalThis.__builtins[key]`.
- The world mode spawns `local-player` when the place has no player object, then runs the place policy and camera behavior. `testdata/spec-world` is the conformance fixture.
- The release profile's fat LTO needs several minutes and memory when another cargo build is running; use the dev binary for world checks and reserve release for verify.sh.
- GLB decode is `src/glb.rs` `decode`: EXT_meshopt_compression views become plain buffer views, KHR_texture_basisu is promoted by `src/basisu.rs` `promote`, and KHR_mesh_quantization is dropped from the extension lists because Bevy 0.20.1 rejects it. `gltf-check` writes decoded copies into `target/gltf-cache` without clearing it, and loads them with an AssetPlugin root there. The wasm viewer enables Bevy `ktx2` but not `basis-universal`, so it cannot read basis-encoded KTX2; `basisu::transcode_basis_images` rewrites each basis-encoded image (vkFormat undefined: BasisLZ or UASTC) as BC7 KTX2 (vkFormat 145) by default, or RGBA8 with `gltf-check <dir> <project> rgba8` into `target/gltf-cache-rgba8`; BC7 needs `texture-compression-bc` on the GPU, which desktop GPUs have and most mobile GPUs lack; `texture-quality` measures BC7 against RGBA8 per texel; Zstandard levels are inflated with `ruzstd` first, because `build.rs` sets `BASISD_SUPPORT_KTX2_ZSTD=0` through `native/basislz_ktx2.cpp`, which calls the basis-universal ktx2 transcoder. `build.rs` compiles that file against the transcoder headers of the cargo registry copy of basis-universal-sys 0.3.1 (`$CARGO_HOME/registry/src/*/basis-universal-sys-0.3.1/vendor/basis_universal/transcoder`), so that crate must be fetched before a build.

- `src/features_ecs.rs` mirrors `FeatureState` into typed Bevy entities and exposes `NativeClock`, `NativeRandom`, `NativeMathService`; `feature-report` includes `ecs` counts. Keep the old `FeatureState` fields for report compatibility.
- `viewer` uses `DefaultPlugins.set(WindowPlugin ...)` with render/winit/pbr/UI features; headless `world`, `bench`, `det`, `server` and `client` must not depend on a display. `web` generates a static browser report without rendering.
- `tonemapping_luts` requires `zstd_rust` on this Bevy 0.20.1 checkout; enabling it without a zstd backend fails in `bevy_image`.
- `wasm-viewer/` is a standalone excluded crate with its own `Cargo.lock`; do not add it to root workspace members, because Bevy 0.20.1's optional `bevy_anti_alias` metadata forces a full re-resolution of the native lock. Build it with `WASM_PROFILE=release scripts/build-wasm.sh` and `CARGO_TARGET_DIR=target/wasm-viewer`.
- `scripts/build-wasm.sh` expects `target/tools-wasm/bin/wasm-bindgen` 0.2.129, matching `wasm-bindgen = "=0.2.129"` in `wasm-viewer/Cargo.toml`; a mismatched CLI rejects the wasm custom sections.
- The WebGPU WASM scene is isolated from native-only crates on purpose. It uses Bevy `webgpu`, `web`, `default_font`, canvas-mounted `bevy_winit`, and wasm target dependencies for `web-sys`/`js-sys`/`getrandom`; it does not link x11, Lightyear UDP, rquickjs, Avian, or filesystem modes.
- `web/wasm/wasm-boot.js` treats `navigator.gpu` and wasm module load separately from app readiness. Only `window.__BEVY_WASM_READY === true` / `data-app-ready="true"` plus Bevy's `BrowserWebGpu` adapter log proves WebGPU initialization; headless Chromium's Vulkan surface failure is an environment blocker.
- `scripts/serve-wasm.sh` uses port 8092 and `scripts/serve-wasm.py` adds COOP/COEP/CORP, `application/wasm`, `text/javascript`, and no-store; `web/viewer.html` redirects to `web/wasm/`.
- Render Inspector is browser DOM (`web/inspector.js`) fed by Bevy `DiagnosticsStore`; `?inspector=1` or `I` enables `window.__BEVY_INSPECTOR_ENABLED` and Rust publishes `window.__BEVY_INSPECTOR_SNAPSHOT` (a JSON string until the inspector's 250 ms poll parses it). The inspector renders only the snapshot's `shown` list: every entry carries a value or a `reason`, and the page shows `unsupported` with that reason. `scripts/check-inspector.cjs` needs `CDP_URL` pointing at the gm playwriter browser and fails on a null value without a reason.
- `src/render_stats.rs` (shared with `wasm-viewer` by path) times one frame's SIM, LAUNCH, DRAW and CPU total from marks captured at extract, so the four phases describe the same frame under pipelined rendering; the render-world counters come from `RenderVisibleEntities<Mesh3d>` and `ViewLightEntities`. `RenderDiagnosticsPlugin` is added explicitly because `RenderPlugin` adds it only under `tracing-tracy`; its pass timers need `TIMESTAMP_QUERY`, `TIMESTAMP_QUERY_INSIDE_ENCODERS` and `TIMESTAMP_QUERY_INSIDE_PASSES`, and the GPU reason names whichever are missing.

- Source files carry no comments. Put a fact the code cannot express here, after checking it is still true.
- Bench and determinism runs use `TimeUpdateStrategy::ManualDuration` with the exact 64 Hz tick, so one `App::update` is one fixed tick on every machine.
- The benchmark disables `PhysicsTransformPlugin`, `PhysicsInterpolationPlugin` and `IslandSleepingPlugin`. Transform sync is not part of the solver, interpolation is display-only, and sleeping would make fast benchmarks incomparable with jayzee, which never sleeps.
- The network scene must keep `LightyearAvianPlugin` after `ClientPlugins` and `ServerPlugins`, and must disable `PhysicsTransformPlugin` and `PhysicsInterpolationPlugin`. Lightyear owns `Position` and `Rotation` replication, and the Avian transform sync would overwrite them.
- The network scene disables `IslandPlugin` and `IslandSleepingPlugin` for the same rollback reason as Lightyear's avian_3d example.
- The client must insert `PredictionManager::default()`. Lightyear gates every prediction set on its presence, and without it `PredictionHistory` stays empty while `ConfirmedHistory` still fills from replication, which looks like a working connection with no prediction.
- Lightyear 0.31.0's reference example is commit 8a926d6fece6a0cf04c2747de90c01258524fe0d, `examples/avian_3d`.
- The hash is over f32 bit patterns, not jayzee's f64, because Avian's default scalar is f32. `enhanced-determinism` makes the math portable; it does not widen the scalar.
- `panic = "abort"` is set in release. A panic under that profile gives no backtrace; use the dev profile to debug.
- `.cargo/config.toml` sets `target-cpu=native` for x86_64 Linux. A release binary built there does not run on older CPUs. Remove that flag for portable builds.
- `ActionState<PlayerAction>` is filled by leafwing on the client and by Lightyear's server input plugin on the server. Both sides run the same `apply_player_input` system in `FixedUpdate`, which is what makes prediction and authority agree.
- The client report compares `PredictionHistory<Position>::get(tick)` with `ConfirmedHistory<Position>::newest_present()` at the confirmed tick. Comparing current positions would include the client's lead over the server.
- The server is paced at one 64 Hz tick per loop, and the client at 60 Hz with Lightyear syncing `Time<Fixed>`. A dedicated server can run unpaced, but then verification timing becomes machine-dependent.
- Baseline on the 12-core container, measured back-to-back with jayzee: 0.40 ms vs 0.43 at 500 bodies, 1.04 vs 2.78 at 2000, 1.88 vs 8.96 at 5000, 3.56 vs 28.12 at 10000. A later run must be compared against these on the same host before it is called a regression.
- `game16-report` is emitted from `src/world.rs` using `src/script/mod.rs::game16_report`: it scans `/workspace/extra/game-16` `ctx.*` tokens, parses `__make_ctx` keys from `src/script/prelude.js`, and labels each context key/host bridge with native ECS, `FeatureState`, or deterministic local-shim provenance. `scripts/check-game16-api.cjs` runs `hall` and `main` for 120 ticks and exits non-zero on script errors, missing API, or uncovered usage; use it instead of claiming parity from `FEATURE_MATRIX.md` doc rows alone.
- `Host::world()` asserts instead of dereferencing a null pointer, and `ScriptEngine::shutdown()` clears QuickJS global bridge/context references plus persisted module/factory values before runtime teardown. Keep `api_report()` and `game16_report()` free of QuickJS evaluation; `world` clears the ECS pointer after each tick and a report-time callback would otherwise hit a stale pointer.
- `src/globe.rs` is the spherical world: `GlobeWorld` comes from the place's `globe:` block (`testdata/spec-world/places/globe` is the headless fixture, with place gravity zero). Chunks are Bevy `Mesh` plus Avian `Collider::trimesh` and stream around `GlobeFocus`, the first `GlobeBody`'s position, within `streamRadius`. `chunkSpan` is radians while the report prints degrees. `surface_position` altitude is above terrain, not above the radius. Gravity is applied to `LinearVelocity` in `FixedUpdate`, and bodies are snapped to the surface in `FixedPostUpdate` between `PhysicsSystems::StepSimulation` and `Writeback`. The viewer skips the flat ground and orbit camera when a place has a `globe` block.
- `places/<place>/sim.js` is the place program: `run_place_program` calls its exported `tick(ctx)` every `cadence` (`ms` or `s` suffix), with one persistent ctx per place from `__place_ctx`, so flags such as `ctx.__safeDestroy` survive across ticks. A place with no `sim.js` runs nothing from this path.
- `world.config.yaml` `player: templates/player.js#player` is spawned by the script host on its first tick (`ensure_player`), and `world.rs` skips the bare `local-player` when `WorldState.extra.player` is set. Without a template the bare player still spawns.
- `__wrap` in the prelude: a nested proxy must sync the root key (it passes its parent's `sync`). A nested proxy that writes its own object as the top-level key replaces the whole place state with a child record.
- The mirror batching bound in `scripts/check-viewer-batching.cjs` is `shapesCreated` (`MIRROR_SLOTS` 1, `MIRROR_PROXY` 0) plus `MIRROR_SLACK` 1, one extra (shape, material) pair. The floor is measured on neon `main`, the fixture and spec-world `test`, where each mesh shape reaches the mirror path in exactly one material. The slack lets one second material on an existing shape pass; a shape split across three materials still fails. Raise any term only after measuring why.
- The compressed-format device path: `VIEWER_DISABLE_BC=1` / `?disable-bc=1` and `VIEWER_DISABLE_ASTC=1` / `?disable-astc=1` put the named feature in `WgpuSettings::disabled_features`, so the device request leaves it out and `CompressedImageFormatSupport` reports it absent; the viewer then takes BC7, ASTC 4x4, ETC2 or RGBA8 in that order. The NVIDIA hardware adapter reports BC and SwiftShader's fallback reports BC, ASTC and ETC2, so reaching the other paths on this host needs the selectors plus `?adapter=software`. wgpu 30's web backend drops `forceFallbackAdapter`, so `web/wasm-boot.js` selects the fallback adapter itself. Witnesses: `scripts/check-device-bc-fallback.cjs`, and `scripts/check-device-format-fallback.cjs` (`FORMAT=etc2` for ETC2). A format's visual is judged against an RGBA8 render on the same adapter (`scripts/check-neon-wasm-models.cjs` modes `rgba8-software`, `astc4x4`, `etc2`), because this tree has no CPU ASTC or ETC2 block decoder. Every capture mode passes `still=1`, which holds the wasm viewer's orbit and spin at zero; both run on wall-clock time, and without it two renders of the same model differ (RGBA8 against RGBA8 gave 43 of 64 pairs under 30 dB).
