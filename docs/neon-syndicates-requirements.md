## 4. Scripting and runtime the game expects

The scripts run in the Spawn ctx runtime: behaviors receive `ctx` with `ctx.self`, `ctx.place`, `ctx.world`, `ctx.session`, `ctx.params`, `ctx.music`, `ctx.quad/tri/color/emissive/roughness/metalness/albedo/attribute`, `ctx.on/emit`, `ctx.changed`, `ctx.sleep`, `ctx.after`, `ctx.query`, `ctx.destroy`, `ctx.attach`, `ctx.cross`, `ctx.log`. Imports from `builtin/*` are ES modules backed by the engine.

The engine verb registry extracted from the runtime bundle contains exactly six verbs: `attach`, `cross`, `destroy`, `emit`, `query`, `spawn`. Bevy's `__make_ctx` provides the first five; `spawn` is absent.

## 5. Missing API verbs and features in Bevy

Verbs the game calls directly (highest priority first):

1. `ctx.spawn(template, at)`: creates an object from a spec and optional `feetPosition` grammar. Used by about 40 files (`sys/streetlife.js`, `sys/guide.js`, `sys/soundscape.js`, `commander.js`, `camera.js`, `lib/models.js`, `core/spawn.js`). Without it the squad, pedestrians, drones, guide markers and soundscape never exist.
2. `ctx.canvas(width, height)`: an offscreen 2D canvas whose pixels become a texture. Used by `tex-landmark.js`, `tex-holo.js`, `tex-hoload.js`.
3. `ctx.texture(path)`: a texture handle for TSL `texture(...)` nodes. Used by 5 material scripts and `look-default.js`.
4. `ctx.attribute(name, value)`: geometry attribute tagging (window kinds 7001 to 7005). Used by `gen/tower.js` unguarded and by `d-arcology.js` and `d-harbor.js` guarded.
4a. `ctx.bone(name)`: geometry builder bone selection. Used by `gen/gunship.js` and `gen/person.js`.

Builtin exports missing from the Bevy `builtin_exports` list:

5. `builtin/tsl` `exp2` and `cameraViewMatrix` (both imported by the game). Duplicate names throw at module declaration, so add them once.

Context members that are safe to leave absent: `ctx.purchase` (optional chain), `ctx.uvProjection` (assignment only), `ctx.__*` internal state.

Stubs in Bevy that the game relies on for correctness (not missing, but not real): `ctx.sql.*` returns empty rows, `ctx.proposePurchase` returns a string, `ctx.presence` reports everyone online, `ctx.job` and `ctx.awaitJob` return placeholder records, `ctx.getObjectBoneNames` and `ctx.getObjectMorphTargetNames` return empty lists, `ctx.getObjectSocket` returns null, `ctx.getVibeAudio` returns a synthesized object, `ctx.getPixelProvenance` returns a local shim.

Config features with no Bevy path (silently ignored by the loader):

6. Touch input surfaces (`inputs.touch`, `scripts/touch.js`, CSS `style` for buttons), touch gestures and pinch.
7. Buyables (`buyables`, `onPurchase` scripts, `imageUrl`).
8. `engine.networking.mode: multiplayer` and `engine.ui.theme.font` (Geist Pixel Square font loading).
9. `audio` block (`maxVoices`, `cullBeyond`) and `sound`/`music` playback from the mp3 set.
10. `atmosphere.look.toneMapping: agx` and look params, `atmosphere.clouds`, `atmosphere.moon`, `atmosphere.sky` (`realistic`/`hosek`), `timeOfDay`, `cycle.frozen`, `terrain.materials[].textureScale`, `material.pbr` flag.
11. Object fields `audience` (local versus all) and `visibleRange` culling.
12. Named primitive kinds used as character or prop types (`police`, `civ`, `agent`, `sdrone`, `contract`, `cat`, `board`, `vip`, `guard`, `pigeons`, `rat`, and about 25 more). These are expected to come from `scripted` generators in the game, but the loader must not reject unknown kinds.
13. HDR environment (`hdr`) and the 9 missing GLBs and 61 missing MP3s plus 7 missing PNGs. These are asset fetch gaps, not runtime gaps; music is required only for playback, not for load.

## 6. Minimal order to make it load

Ordered so that each step is testable before the next:

1. Read `world/world.config.yaml` and `places/main/config.yaml` (name, defaultPlace `main`, mode 3d, gravity, spawn point, atmosphere). The Bevy loader already reads these; the unsupported keys are only ignored.
2. Add `ctx.spawn` to the prelude, forwarding to the existing spawn/ECS host verb. This unblocks the behavior modules `arrival.js`, `sys/guide.js`, `sys/streetlife.js`, `sys/soundscape.js`, `core/spawn.js` and `commander.js`.
3. Add `exp2` and `cameraViewMatrix` to the `tsl` export list in `builtin_exports`.
4. Make the flat starter terrain generator (`scripts/flat-starter-terrain.js`) and the 4 terrain materials load (albedo PNGs `cdn/texture-terrain-*`). These come from `assets/cdn`.
5. Load the camera and player templates (`templates/camera.js#camera`, `templates/player.js#player`), the lighting script `scripts/lighting.js` (guarded for `ctx.texture`) and the look script `scripts/look-default.js`.
6. Load the place simulation `places/main/sim.js` with its data imports (the 28 YAML files under `scripts/lib/data/`), which pull in `sys/*` and `core/*`.
7. Add `ctx.canvas` and `ctx.texture`, then the material and texture scripts (`*-mat.js`, `tex-*.js`) and the `gen/*.js` geometry builders. `ctx.attribute` is needed before `gen/tower.js` runs unguarded.
8. Load the GLB models (`clip-*.glb`, plus the 64 `value.*.glb` set) and the character and vehicle generators that reference them.
9. Load the UI: `scripts/ui.js` render, `ui/nametag.js`, the Geist Pixel Square font. Then `scripts/hud/*.js` and `scripts/sys/feel.js` and `scripts/sys/match.js`.
10. Add touch surfaces and the input axes once the desktop path renders (`scripts/touch.js`).
11. Add audio (`audio` block, 95 SFX and voice MP3s present) and then the 61 missing music and SFX files when they are re-fetched.
12. Buyables and networking mode are last: they need the purchase and presence services, which are stubs today.

Verification: run `world /workspace/neon-syndicates world` (or the `testdata/spec-world` conformance harness) after each step, and check `game16-report` `missingApi` for the ctx names above. Use the dev binary, not release, per AGENTS.md.

The owner's figure of 115 missing host APIs does not match any scan of this world, the whole neon-syndicates project, or the game-16 corpus. Of the 10 entries, 2 are `.length` and `.push` on `__soundQ`, so they name 8 host keys.

Root cause of zero objects and behaviours: `places/main/sim.js` is the place program (`export const cadence`, `export function tick(ctx)`). The runtime only ran `config.policy` hooks, and this place has no `policy`, so `tick` never ran, and `templates/player.js#player` (with `behavior: scripts/commander.js`) was never spawned. The baseline world spawned one bare `local-player` with no behaviour.

Implemented:

- `ctx.spawn(spec)` and `ctx.spawn(id, spec)` through the existing `__jayzee` bridge.
- Shim keys on `ctx`: `uvProjection`, `__feelRaw`, `__glass`, `__safeDestroy`, `__soundGun`, `__soundQ`, `__soundRaw`, all persisted by the per-place ctx.
- `builtin/tsl` exports `cameraViewMatrix` and `exp2`, which `scripts/crowd-mat.js` and `scripts/lighting.js` import.
- `run_place_program` runs `places/<place>/sim.js` `tick(ctx)` at its `cadence`.
- `ensure_player` spawns the configured player template on the first tick.
- `__wrap` nested proxies now sync the root key, which had been replacing `ps.squads` with a squad record.
- Script hook errors now carry the error message.
- Unit tests: `script::tests` (cadence parsing, ctx keys, builtin export uniqueness and tsl names) and `features::tests` (seeded RNG repeatability, report is an object).

Verified (dev profile):

- `target/debug/bevy-jayzee world /workspace/neon-syndicates/world main 120` exits 0 with `"errors":0`, `missingApiCount` 0, `"objects":58`, `"bodies":9`, `"behaviors":1`, `"models":9`, `"scripted":11`, `"moduleCount":6`.
- `node scripts/check-game16-api.cjs` (default game-16 corpus, places `hall` and `main`, 120 ticks) exits 0 with `"ok": true`.

Not done: the camera template (`templates/camera.js#camera`, with `behavior: scripts/camera.js`) is not spawned, because the world config's `camera` is not an object spec. The camera behaviour therefore stays unloaded, and the scene still runs without it.
